# LAN transfer record profile

## LAN revision 3: 512 KiB chunks

Current apps advertise Bonjour TXT `v=3` and select record profile 4 before EDHOC. DATA plaintext is bounded to 524416 bytes, envelopes to 524447 bytes, with wire version 4 in the TCP frame and authenticated record header. The exporter context is `["aniCe LAN transfer 512", 1, 524416, initiatorBinding, responderBinding, direction, purpose]`. Other header fields, nonce construction, AES-256-GCM, trust validation and deadlines are unchanged. Four queued envelopes admit at most 2097788 envelope bytes.

Transfer capability 4 permits 524288-byte file chunks and eight-chunk credit (4194304 file bytes). Capability 2 and 3 advertisements retain their original 131072/262016-byte bounds. Android continues to resolve revisions 1/2 with their original profiles; current Mac listeners require revision 3/profile 4, so update both peers. Standard/BLE limits stay unchanged. Transfer ingress remains capped at 2097152 bytes including active work; transport and feature backpressure remain independent. The existing small qualification probe and constrained 64-KiB/two-chunk fallback still apply.

## Legacy revision 2

Legacy LAN revision 2 advertises `_anice._tcp` with TXT `v=2`. Android selects profile 3 only for that revision; `v=1` selects the existing standard profile. The selected profile is fixed before EDHOC, never inferred from incoming frames. macOS revision 2 accepts profile 3 only. Update both apps for larger LAN records. BLE retains profile 1 unchanged.

Profile 3 uses `version:u8=3 || envelopeLength:u32be || envelope` framing, 2–262175 bytes per envelope and one incomplete frame. Assembly follows the [LAN deadline policy](README.md): ten seconds absolute before secured readiness and for partial headers/handshake envelopes; established encrypted-record envelopes allow ten seconds without progress, capped at sixty seconds from the first header byte. Handshake envelopes retain the 4096-byte limit. AES-256-GCM record header is `version:u8=3 || kind:u8 || sequence:u64be || plaintextLength:u32be`; DATA plaintext is at most 262144 bytes. Other record kinds have empty plaintext. Directional counters, nonce XOR, 16-byte tags, AAD, one-hour lifetime and 2^20 record limit are unchanged. Exporter context is deterministic CBOR `["aniCe LAN transfer", 1, 262144, initiatorBinding, responderBinding, direction, purpose]`. Profile mismatch fails authentication/readiness; TXT records confer no trust.

Native identity, key presence/protection, durable journal and pinned trust checks remain live for every authenticated operation. Larger records amortize this work; no security-validation cache or timeout is added. Android performs native validation before sealing and after awaited transport submission; generation/deadline checks bracket synchronous encryption. Receive authentication is synchronous, followed by native validation before counter advancement or application delivery. No plaintext reaches features after a failed native/trust check. At most four queued envelopes and 1048700 queued bytes are admitted. Write deadlines remain ten seconds absolute.

Transfer envelope tag/version remain `["aniCe transfer", 1, ...]`. Capability version 2 is accepted only on authenticated profile 3, with max-chunk-bytes 1–131072 and max-window 1–8. Capability version 3 is also profile-3-only and allows max-chunk-bytes 1–262016 with max-window 1–8, filling the existing 262144-byte DATA plaintext budget while leaving room for the maximum transfer envelope metadata. Capability version 4 is profile-4-only and permits max-chunk-bytes 1–524288 with max-window 1–8 inside the 524416-byte DATA budget. Version 1 retains 3072-byte chunks and 64-record credit. Profile-3 peers advertise capability 2 before capability 3; profile-4 peers advertise capabilities 2, 3 and 4 in order. Both peers advertise before sending; the chunk ceiling is the minimum of local channel capacity and peer capability; senders may use smaller chunks within advertised credit, and older capability versions retain their original limits. Other transfer fields, hashing, approval and result semantics are unchanged. Profile 3 and profile 4 transfer CBOR budgets are 262144 and 524416 bytes respectively, with the existing 512-item/eight-level limits. BLE and standard-channel CBOR limits remain unchanged.

Android sets profile-3 and profile-4 socket send/receive buffer hints to 4 MiB before connect; effective buffer sizes are platform-controlled. The isolated 4-MiB bulk probe retains its separate receive hint.
