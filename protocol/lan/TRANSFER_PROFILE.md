# LAN transfer record profile

Production LAN revision 2 advertises `_anice._tcp` with TXT `v=2`. Android selects profile 3 only for that revision; `v=1` selects the existing standard profile. The selected profile is fixed before EDHOC, never inferred from incoming frames. macOS revision 2 accepts profile 3 only. Update both apps for larger LAN records. BLE retains profile 1 unchanged.

Profile 3 uses `version:u8=3 || envelopeLength:u32be || envelope` framing, 2–262175 bytes per envelope, one incomplete frame and the existing absolute ten-second assembly deadline. Handshake envelopes retain the 4096-byte limit. AES-256-GCM record header is `version:u8=3 || kind:u8 || sequence:u64be || plaintextLength:u32be`; DATA plaintext is at most 262144 bytes. Other record kinds have empty plaintext. Directional counters, nonce XOR, 16-byte tags, AAD, one-hour lifetime and 2^20 record limit are unchanged. Exporter context is deterministic CBOR `["aniCe LAN transfer", 1, 262144, initiatorBinding, responderBinding, direction, purpose]`. Profile mismatch fails authentication/readiness; TXT records confer no trust.

Native identity, key presence/protection, durable journal and pinned trust checks remain live for every authenticated operation. Larger records amortize this work; no security-validation cache or timeout is added. Android performs native validation before sealing and after awaited transport submission; generation/deadline checks bracket synchronous encryption. Receive authentication is synchronous, followed by native validation before counter advancement or application delivery. No plaintext reaches features after a failed native/trust check. At most four queued envelopes and 1048700 queued bytes are admitted. Frame and write deadlines remain ten seconds.

Transfer envelope tag/version remain `["aniCe transfer", 1, ...]`. Capability version 2 is accepted only on authenticated profile 3, with max-chunk-bytes 1–131072 and max-window 1–8. Version 1 retains 3072-byte chunks and 64-record credit. Both peers advertise before sending; chunk size is the minimum of local channel capacity and peer capability, and version 1 always selects the original limits. Other transfer fields, hashing, approval and result semantics are unchanged. Profile-3 transfer CBOR has a 262144-byte budget with the existing 512-item/eight-level limits. BLE and standard-channel CBOR limits remain unchanged.

Android sets profile-3 socket send/receive buffer hints to 2 MiB before connect; effective buffer sizes are platform-controlled. The isolated 4-MiB bulk probe retains its separate receive hint.
